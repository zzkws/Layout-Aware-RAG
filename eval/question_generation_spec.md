# 场景化客户问题 生成规范（给出题 LLM 用）

目标：批量产出**拟真的企业客户售前咨询**——提问者多为**非技术人员**（采购、
产品经理、项目负责人、老板、非晶振专业的工程主管），带着**自己的应用场景和
困扰**来找石英晶振技术方案。系统(RAG)要把场景翻译成参数、推荐型号、给指标并
附证据引用。

> 与 v1（直接报参数/型号的查询题）的区别：场景题**更难、更真实**，因为客户用
> 业务语言，不用 datasheet 术语，强烈考验 query 改写与召回。

---

## 1. 一道好场景题的硬性要求

✅ **必须做到**
- **非技术口吻**：描述「我们是做什么的 + 在做什么产品 + 遇到什么问题/担心什么」。
- **场景具体**：行业 + 产品 + 工作环境（温度/功耗/尺寸/EMI/成本）+ 一个明确诉求。
- **不点参数名、不点型号**：客户不知道"老化率""相位噪声""TOC2522"。让系统去翻译。
- **落到一个可回答的诉求**：最终有个具体问题（"有没有合适的方案/推荐一款/关键
  指标是多少/能不能满足"）。
- **2–5 句**，像真人发来的咨询邮件/微信，可带一点背景噪声（预算、量产、客诉）。

❌ **避免**
- 照 datasheet 抄（"请问 TOC2522 的 10 年稳定度"——这是 v1 风格，不是场景题）。
- 编造语料里根本没有的产品类别（如压电传感器阵列）当作可答题。
- 一题塞 5 个独立问题（最多 1 主诉求 + 1 附带）。

---

## 2. 正/反例

**❌ 太像 datasheet（非场景）**
> TOC2522 的相位噪声和老化率是多少？

**✅ 场景化（非技术、有情境）**
> 我们是一家做小型 5G 室分基站的初创公司，团队里没有晶振方面的专家。设备对时钟
> 同步要求比较高，客户也很在意长期跑下来时间会不会漂。能不能帮我们推荐一款稳定
> 度高、相位噪声低的晶振，并告诉我几个关键指标，方便我们评估？

**✅ 带宽温痛点（智能电表）**
> 我是一家电表厂的产品经理。我们的表卖到东北，冬天有用户反馈时间走不准、对账
> 对不上。我们现在用的是普通晶体。想问下你们有没有更适合宽温环境、走时更准、又
> 省电的时钟方案？

**✅ 库外压力题（车规认证，语料答不了）**
> 我们做车载 T-BOX，采购要求晶振必须是车规级、过 AEC-Q200，工作温度要能到
> +105℃。你们有符合的型号吗？给我个料号和认证报告。

## 3. 生成时同时产出的字段（draft 标注，后续人工/读图核实）

每生成一题，输出下列 JSON（与 `schema.json` 对齐）：

```json
{
  "id": "tkd-scn-XXX",
  "question": "（场景化中文/英文问法）",
  "lang": "zh",
  "persona": "产品经理",
  "intent": "solution_recommendation",
  "difficulty": "medium",
  "answerable": true,
  "customer_profile": "智能电表厂商-产品经理",
  "scenario": "电表销往东北，宽温，量产中出现走时偏差客诉",
  "pain_point": "低温下走时不准、希望省电",
  "underlying_need": "低功耗 RTC / 温补时钟；宽温频率稳定度",
  "gold_products": ["TR8010"],
  "gold_chunks": ["<待检索/标注>"],
  "gold_facts": ["<待读图核实>"],
  "must_not": ["编造未在资料中的认证/价格"],
  "verify_status": "unverified",
  "notes": "gold 待人工读图核实"
}
```

`underlying_need` 是桥梁：把非技术诉求翻译成参数/产品族，**只用于评测和找 gold，
绝不能出现在 question 里**（否则就泄题了）。

## 4. 覆盖矩阵（让 LLM 按格子产出，避免同质化）

**场景行业 × 产品族**（√=语料可较好支撑，▲=部分/需引导联系工厂）：

| 行业场景 | 对应需求 | 产品族（gold） | 可答性 |
|----------|----------|----------------|--------|
| 5G/通讯基站、守时授时 | 高稳定、低相噪、低老化 | OCXO (TOC2522/2525) | √ |
| 电信传输/同步(PTP/SyncE) | 稳定度+holdover | OCXO/高档TCXO | √ |
| 智能电表/水表/计量 | 低功耗计时、宽温 | RTC (TR8010)、32.768k晶体 | √ |
| GPS/GNSS/北斗定位 | 小尺寸高精度参考时钟 | TCXO (TC2520) | √ |
| 服务器/交换机/光模块 | 高速差分时钟 | SPXO LVPECL/LVDS/HCSL (LV/TLV系列) | √ |
| 安防摄像头/IPC | sensor 时钟、低成本小封装 | 晶体 (M1210/M2016)、XO系列 | √ |
| 无线模块(BLE/WiFi) | 主时钟 + 32.768k | 晶体 (M1008/M1210) + 音叉 | √ |
| 充电桩/工业控制 | 宽温稳定计时 | TCXO (TC2520/TC5032) | √ |
| 车载/车规 | AEC-Q200、-40~+105℃ | （语料未声明车规） | ▲ 引导联系工厂 |
| 医疗/特殊认证、报价/样品 | ISO认证、MOQ、价格 | （datasheet 无此信息） | ✗ 礼貌拒答 |

**配额建议**（首批 ~30 场景题）：可答题 24（每个 √ 行 3 题：难/中/易各档、
中英混合），▲ 边界题 3，✗ 库外题 3。务必保留 ▲/✗ 题——它们是幻觉护栏的考核。

---

## 5. 难度怎么分

- **easy**：场景单一、诉求清楚，单一产品族单一指标即可答（"省电的计时方案"）。
- **medium**：需推荐型号 + 给 2–3 个关键指标，或带一个约束（宽温/小尺寸）。
- **hard**：多约束权衡（稳定度 vs 功耗 vs 成本）、需对比多型号、或跨表/多跳；
  以及 ▲ 边界题（部分满足，需说明限制）。

---

## 6. 评分如何与场景题对齐（补充 README 的 6 维度）

场景推荐题额外看：
- **推荐恰当性**：推荐的产品族/型号落在 `gold_products` 内（推荐错族直接 fail）。
- **指标可用且正确**：给出的关键指标命中 `gold_facts` 且数值/单位正确。
- **边界诚实**：▲/✗ 题要明确说明"资料未覆盖/建议联系泰晶"，不得硬凑或编造。
